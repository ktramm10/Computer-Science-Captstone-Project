# AI Data Product Documentation

## Product Summary

The data product is a prompt to scene assistant for the C++ game engine. It uses a scikit learn text classification pipeline to predict the game genre for a designer prompt, then maps that genre to scene templates, entities, and engine components used to generate a starter scene.

## Raw and Cleaned Datasets

Raw dataset: `src/AI/training.csv`

Cleaned dataset: `src/AI/cleaned_training.csv`

The raw dataset contains labeled game design prompts with expected genre, entities, components, and scene template. The cleaned dataset is generated by the same Python workflow used for training. Cleaning includes whitespace normalization, prompt length limiting, empty training row filtering, schema validation, and semicolon list normalization for entities and components.

Cleaning/export command:

```powershell
.\.venv\Scripts\python src\AI\train_model.py --export-cleaned
```

Cleaning and training source code: `src/AI/train_model.py`

## Analysis and Data Product Code

The descriptive analysis code lives in `src/AI/train_model.py` and computes genre, entity, component, missing-cell, and prompt-length summaries. The predictive data product code also lives in `src/AI/train_model.py` and constructs this pipeline:

- `TfidfVectorizer(ngram_range=(1, 2), lowercase=True)`
- `LogisticRegression(max_iter=1000)`
- `sklearn.pipeline.Pipeline`

The C++ application integration code is in:

- `src/AIPromptBridge.cpp`
- `src/AIPromptBridge.h`
- `src/EditorUI.cpp`
- `src/ProjectPaths.h`

Runtime file paths are resolved from the project root through `src/ProjectPaths.h`. This lets the executable load scenes, scripts, assets, and AI files even when it is started from the repository root instead of from `build/Debug`.

## Hypotheses

Primary hypothesis: a supervised text classifier trained on short game design prompts can predict the intended game genre well enough to select a useful starter scene template.

Acceptance rule: accept the hypothesis if validation accuracy is at least 0.80 and the predicted genre maps to a scene template with usable entities and components.

Current assessment: accepted. The latest validation run reported 0.90 accuracy, and supported labels map to scene-outline JSON files in `src/json/scene_outlines/`.

Secondary hypothesis: exposing diagnostics and visualizations inside the AI Prompt workflow improves reviewability of the data product.

Acceptance rule: accept if the in app dashboard displays model confidence, model accuracy, dataset label distribution, and requirement coverage after a prompt is generated.

Current assessment: Accepted. The AI Prompt dashboard displays metric gauges, a label histogram, and requirement coverage tiles.

## Visualizations and Storytelling

The project supports data storytelling in two places:

- Console report from `src/AI/train_model.py`, including genre/entity/component bar charts and accuracy reporting.
- In-app AI Prompt dashboard in `src/EditorUI.cpp`, including metric gauges, a training label histogram, a dataset-health summary, requirement coverage tiles, and raw diagnostics JSON.

The subject being detected is the intent of a game design prompt. The model detects this by converting prompt text into TF-IDF unigram and bigram features, then classifying the feature vector into a genre label such as `platformer`, `puzzle`, `runner`, `space_shooter`, or `top_down_shooter`.

## Accuracy Assessment


Latest observed result:

- Labels: platformer, puzzle, runner, space_shooter, top_down_shooter
- Evaluation kind: validation

The workflow uses a stratified train/test split when the dataset is large enough and each class has enough rows. If the dataset is too small, it falls back to training accuracy and labels the result accordingly.
